# Architecture Decision Records

Записи архитектурных решений (ADR) по RecallApp. Один файл - одно решение: контекст, рассмотренные варианты, выбор и последствия.

## Конвенция

- **Централизованное хранение**: все ADR здесь, в `docs/adr/`.
- **Имя файла**: `NNNN-имя-adr-записи.md` со сквозной нумерацией (`0001-`, `0002-`, ...).
- **Область решения** указывается полем **Scope** внутри записи (напр. «Платформа (общее)» или конкретный компонент). Разносим по подпапкам только когда появятся отдельные кодовые базы.
- **Неизменяемость тела.** Правим что угодно в записи, пока она `proposed`. После перехода в любой другой статус тело записи замораживаем на изменение: менять допускается только `Status`, дату и ссылку на преемника. Нужно изменить само решение - заводим новую запись.
- **Статусы**: 
  - см. *Таблица переходов по статусам* ниже.
- **Продуктовые решения (PDR)** живут в wiki, не здесь.

*Таблица переходов по статусам*
| Начальный статус | Переходный статус | Значение итогового статуса |
|---|---|---|
| `-` | `proposed` | Выдвинута на согласование, по сути черновик. Можем редактировать всю запись |
| `proposed` | `rejected` | Рассмотрена и отклонена по каким-то причинам. |
| `proposed` | `accepted` | Согласована и принята в проект |
| `accepted` | `deprecated` | Больше не применяется (подход заброшен, подсистема убрана), прямой замены нет |
| `accepted` | `superseded` | Заменена согласованной новой записью со ссылкой на преемника |
| `deprecated` | `-` | Терминальный статус |
| `superseded` | `-` | Терминальный статус, см. ссылку на преемника |
