# ADR 0006. Доставка push-уведомлений

- **Status:** accepted
- **Date:** 2026-10-16
- **Decision-maker(s):** Aleksandr
- **Owner:** Aleksandr
- **Scope:** Платформа (общее)

## Контекст

Push нужен для удержания: напоминания о повторениях (SRS), стрики, возвраты (§3.6, фаза social, в горизонте). Платформа web-first, значит push - это Web Push в браузер. Нативные мобильные приложения вне горизонта (off-scope).

Данные для доставки (push-подписки/токены, таргетинг) - персональные данные. По 152-ФЗ они должны храниться на территории РФ.

Нужно решить, доставляем push своей системой или через вендора.

## Рассмотренные варианты

1. **Свой web push.** Бэкенд сам реализует Web Push Protocol (VAPID, шифрование payload), рассылку ведёт фоновый воркер через шину сообщений. Из преимуществ полный контроль, данные остаются в нашей инфраструктуре (проще по 152-ФЗ). Минусы: сами пишем и сопровождаем данный модуль; потребуется поднимать под эту задачу воркер и шину; появляется новый компонент, требующий обслуживания.
2. **Push-поставщик.** Доставку, работу с браузерами и ретраи берёт на себя вендор (Sendsay, FCM и прочие). Быстрый старт, меньше своего кода. Минусы: персональные данные уходят на сервера вендора (поставщика), нужен РФ-локализованный; стоит денег, траты зависят от числа пользователей по тарифам; привязка к вендору.

## Решение

Доставляем push через **вендора с РФ-локализацией**, чтобы не писать собственный web-push-стек. 

Кандидат - Sendsay (РФ-провайдер, покрывает push). Стартовый тариф порядка 1000 ₽/мес ≈ 1000 push-сообщений в месяц - приемлемо для 8 месячного горизонта.

- Обязательное требование к вендору: хранение персональных данных в РФ и договор на обработку (152-ФЗ).
- Если подходящего РФ-вендора не найдётся или условия не устроят, то откатываемся на свой web push (вариант 1).

## Последствия

- Не пишем и не держим собственный web-push-стек; доставка на стороне вендора.
- Зависимость от вендора и его тарифов.
- Тариф лимитирован объёмом сообщений; с ростом базы пользователей потребуется переход на более дорогой тариф.
- Перед интеграцией - проверка РФ-локализации вендора и оформление обработки ПД (152-ФЗ).
- На C4-Context внешний бокс «Push-провайдер» - это выбранный вендор.
- Нативные мобилки вне охвата (off-scope). При их появлении ADR дополняется/пересматривается.
