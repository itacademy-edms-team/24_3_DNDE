# ADR 0011. Подход к фронтенду: компонентный SPA

- **Status:** accepted
- **Date:** 2026-10-17
- **Decision-maker(s):** Aleksandr
- **Owner:** Aleksandr
- **Scope:** Платформа (общее)

## Контекст

Платформа web-first, адаптив под десктоп/планшет/телефон (План §4.5). Фронтов два: публичное приложение и служебное (back-office), оба являются веб приложениями (ADR 0002). Фреймворк формально нигде не выбран, однако в ADR 0002 уже упоминали «SPA».

Клиент несёт сложное и количественно большое состояние: карточки и SRS, разные форматы заданий, live-матчи с таймерами, счётом и лидербордом в реальном времени (План §4, realtime-слой). BFF отдаёт данные, а не готовые HTML-страницы (ADR 0002). В связи с этим прогнозируется большая динамика на стороне клиента.

Развилка по подходу: собирать интерфейс как статический многостраничный сайт (html+css+js вручную) или как компонентное SPA на фреймворке.

## Рассмотренные варианты

1. **Статический MPA (html + css + js, без фреймворка).** Минимум настройки, лёгкий первый рендер, SEO работает из коробки, нет оверхеда на бандл. Минусы: богатый интерактив и realtime-UI приходится собирать на ручном DOM, нет компонентной модели, логика дублируется между страницами, stateful-экран матча с ростом фич становится тяжело поддерживать. Плохо ложится на модель взаимодействия с BFF.

2. **Компонентный SPA на React.** Решение, заточенное под большую динамику на клиенте. Декларативный stateful-UI, переиспользуемые компоненты в обоих фронтах, зрелая экосистема с большим количеством примеров и поддерживаемых технологий. Прямо ложится на BFF-взаимодействие. Минусы: сборка и тулинг, размер бандла, SEO требует отдельных решений - чистый клиентский рендер отдаёт краулеру пустую страницу.

## Решение

Фронтенд строим как **компонентное SPA на React** (вариант 2), по одному приложению на контур: публичное и back-office.

Конкретный выбор React (а не Vue/Svelte/Angular) заключается в личных предпочтениях и наличии опыта работы с библиотекой.

## Последствия

- Два SPA-приложения (public, back-office), каждое общается только со своим BFF (ADR 0002).
- Переиспользование компонентов и клиентской логики между контурами.
- Экосистема React/React Native может переиспользоваться, если после горизонта появятся не-web клиенты (ADR 0002).
- SEO/шеринг публичных страниц под угрозой. Гость смотрит фрагменты наборов и лидерборды (План §4) - это публичный контент, который может быть доступен из сети. Чистый CSR не отдаёт информации о таких страничках поисковикам. Потребуются соответствующие решения.
- Появляется сборочный пайплайн (бандлинг, тулинг) - цена за сборку и применение фреймворка.
- На C4-Container оба фронта - контейнеры с технологией «SPA, React».
