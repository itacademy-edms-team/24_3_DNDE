## SRS-01 SRS-планировщик

Планировщик распределённого повторения с растущими интервалами. Работает над **любым извлекающим элементом** (карточка, ввод ответа, числовой, тест, сопоставление, пропуски), а не только карточками: сигнал сложности берётся из Результата проверки независимо от формата. Дивергентные элементы вне SRS (модель §2). Роль — Пользователь. Конкретный алгоритм интервалов — ADR (План §7.1), истории его не фиксируют.

### SRS-01-US-1

**Как** Пользователь, **я хочу** оценивать, насколько трудно далось задание, или чтобы это определялось по моему ответу, **чтобы** система смогла определить наиболее удачное время для следующего повторения материала.

```
Сценарий: сигнал сложности после проверки
  Дано: я ответил на извлекающий элемент (карточка, ввод, числовой и т.п.)
  Когда: получен Результат проверки
  Тогда: формируется сигнал сложности — из самооценки для карточек (снова/трудно/хорошо/легко) или из авто-сверки для проверяемых форматов
  И: сигнал уходит в SRS-запись элемента и влияет на следующий показ
```

### SRS-01-US-2

**Как** Пользователь, **я хочу** чтобы интервал рос при успехе и сокращался при провале, **чтобы** эффективно вспоминать и запоминать материал перед его забыванием.

Критерии приёмки:
- успешное повторение увеличивает интервал до следующего показа;
- неуспех сокращает интервал;
- при повторных успехах интервалы растут (распределённое повторение);
- конкретное правило интервалов задаёт алгоритм (ADR), истории чисел не фиксируют.

### SRS-01-US-3

**Как** Пользователь, **я хочу** начать повторение из того, что подошло к сроку, **чтобы** повторять только реально необходимое для вспоминания.

```
Сценарий: сессия повторения
  Дано: часть моих элементов подошла к сроку повторения
  Когда: я запускаю повторение
  Тогда: в сессию попадают элементы, у которых наступил срок
  И: каждый проверяется в своём формате
```

Дополнительно:
- если срок не наступил ни у одного элемента, сессия повторения пуста и может предложить новые элементы.

### SRS-01-US-4

**Как** Пользователь, **я хочу** видеть, сколько элементов ждёт повторения и когда следующее, **чтобы** удобнее было планировать следующее занятие.

Критерии приёмки:
- видно число элементов, ждущих повторения сейчас;
- видно время следующего запланированного повторения;
- счётчик обновляется после сессии.

### SRS-01-US-5

**Как** Пользователь, **я хочу** чтобы новые элементы вводились в расписание постепенно, **чтобы** не получить завал из всего набора сразу.

Критерии приёмки:
- новые, ещё не изучавшиеся элементы вводятся в расписание постепенно;
- есть лимит новых элементов за сессию или день (значение — настройка);
- введённый элемент дальше планируется наравне с остальными.

## SRS-02 Чередование

Смешивание элементов в сессии (interleaving): обучение различению вместо узнавания по порядку. Охват — внутри набора и между несколькими выбранными наборами или группой. Зависит от SRS-01. Роль — Пользователь.

### SRS-02-US-1

**Как** Пользователь, **я хочу** чтобы в сессии темы и наборы шли вперемешку, а не блоками, **чтобы** мозг учился запоминать и различать материал по существу, а не по порядку следования.

```
Сценарий: смешанная сессия
  Дано: в сессии есть элементы из разных тем или наборов
  Когда: я прохожу сессию с включённым чередованием
  Тогда: элементы идут вперемешку, а не блоками по теме
```

Дополнительно:
- охват работает и внутри одного набора, и между несколькими выбранными наборами или группой.

### SRS-02-US-2

**Как** Пользователь, **я хочу** чтобы в сессии смешивались разные типы элементов, **чтобы** не отвечать на автопилоте, а думать и вспоминать на каждый элемент.

Критерии приёмки:
- в сессии смешиваются разные типы элементов;
- по возможности подряд не идут однотипные элементы.

### SRS-02-US-3

**Как** Пользователь, **я хочу** включать и выключать чередование, **чтобы** выбирать между смешанной и блочной практикой.

Критерии приёмки:
- чередование можно включить и выключить;
- при выключенном чередовании порядок блочный (тема за темой, тип за типом).

### SRS-02-US-4

**Как** Пользователь, **я хочу** чтобы чередование не ломало приоритет расписания SRS, **чтобы** сперва видеть то, что реально уже пора повторить.

Критерии приёмки:
- чередование меняет только порядок подачи, не состав очереди;
- что пора повторить, решает SRS-01 (срок в приоритете);
- чередование перемешивает уже отобранное к показу.

## SRS-03 Многоформатная проверка

Один материал проверяется разными форматами по повторам. Зависит от SRS-01 и CORE-03 (дистракторы для теста). Роль — Пользователь.

### SRS-03-US-1

**Как** Пользователь, **я хочу** чтобы один материал проверялся разными форматами по повторам, **чтобы** вспоминать материал по существу, а не по форме вопроса.

```
Сценарий: смена формата по повторам
  Дано: один материал уже проверялся в одном формате
  Когда: наступает следующий повтор
  Тогда: тот же материал может быть предъявлен другим допустимым форматом (карточка, ввод, выбор, сопоставление)
```

### SRS-03-US-2

**Как** Пользователь, **я хочу** чтобы формат проверки подходил под тип элемента и его данные, **чтобы** не получить тест с выбором там, где вариантов не из чего собрать.

Критерии приёмки:
- формат подбирается по типу элемента и наличию нужных данных;
- тест с выбором применяется, только если есть из чего собрать дистракторы (другие элементы набора, CORE-03);
- неподходящие элементу форматы не предлагаются.

### SRS-03-US-3

**Как** Пользователь, **я хочу** при желании ограничить, какими форматами меня проверяют, **чтобы** убрать неудобные или ненужные на мой взгляд форматы.

Критерии приёмки:
- можно ограничить набор форматов, которыми идёт проверка;
- исключённые форматы не предъявляются;
- ограничение не мешает SRS планировать повторы.
