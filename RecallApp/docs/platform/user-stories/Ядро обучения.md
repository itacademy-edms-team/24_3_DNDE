## CORE-01 Флеш-карточки

Классический режим карточек: показ, переворот, навигация, перемешивание, прогресс. Без оценки «знаю / не знаю» — это территория заучивания с SRS (CORE-06). Роль везде — Пользователь.

### CORE-01-US-1

**Как** Пользователь, **я хочу** открыть набор в режиме карточек, **чтобы** учить его по одной карточке.

Критерии приёмки:
- из набора доступен запуск режима карточек;
- открывается первая карточка набора лицевой стороной;
- для пустого набора режим не запускается, показывается подсказка добавить карточки.

### CORE-01-US-2

**Как** Пользователь, **я хочу** видеть лицевую сторону и переворачивать карточку, **чтобы** проверить себя, вспомнив оборот.

```
Сценарий: переворот карточки
  Дано: открыта карточка лицевой стороной
  Когда: я нажимаю на карточку
  Тогда: показывается её оборот
  Когда: я нажимаю ещё раз
  Тогда: снова показывается лицевая сторона
```

Дополнительно:
- если у стороны есть медиа, оно показывается вместе с текстом;
- переворот не меняет текущую позицию в наборе.

### CORE-01-US-3

**Как** Пользователь, **я хочу** листать карточки вперёд и назад, **чтобы** двигаться в своём темпе.

Критерии приёмки:
- доступны переходы к следующей и предыдущей карточке;
- «вперёд» показывает следующую карточку лицевой стороной;
- «назад» показывает предыдущую карточку лицевой стороной;
- за границы набора листать нельзя: на первой карточке нет «назад», на последней нет «вперёд».

### CORE-01-US-4

**Как** Пользователь, **я хочу** перемешать карточки, **чтобы** не запоминать материал по порядку.

```
Сценарий: перемешивание колоды
  Дано: открыт режим карточек
  Когда: я включаю перемешивание
  Тогда: порядок карточек становится случайным
  И: прогон начинается с первой карточки нового порядка
  Когда: я выключаю перемешивание
  Тогда: возвращается исходный порядок набора
```

### CORE-01-US-5

**Как** Пользователь, **я хочу** видеть прогресс по колоде, **чтобы** понимать, сколько осталось запомнить.

Критерии приёмки:
- виден индикатор позиции: номер текущей карточки и общее число (например, 3/20);
- индикатор обновляется при навигации;
- индикатор считает просмотренные карточки текущего прогона (оценки «знаю / не знаю» в этом режиме нет).

## CORE-02 Ввод ответа

Текстовый ответ с проверкой по эталону. Формат извлекающий: пользователь вспоминает и вписывает, а не узнаёт. Элемент возвращает Результат проверки; расписание повторений — отдельная фича SRS-01, здесь его нет. Роль — Пользователь.

### CORE-02-US-1

**Как** Пользователь, **я хочу** вписать ответ на карточку текстом, **чтобы** проверить, что помню, а не просто узнаю.

```
Сценарий: ввод ответа
  Дано: показана карточка с вопросом
  Когда: я ввожу ответ текстом и подтверждаю
  Тогда: ответ принимается и сверяется с эталоном
```

Дополнительно:
- пустой ответ не засчитывается как верный.

### CORE-02-US-2

**Как** Пользователь, **я хочу** видеть, верен мой ответ или нет, с эталоном, **чтобы** понять, где ошибся.

```
Сценарий: проверка ответа
  Дано: я ввёл ответ и подтвердил
  Когда: ответ совпадает с допустимым эталоном по правилу сверки
  Тогда: ответ отмечается верным
  Когда: ответ не совпадает ни с одним эталоном
  Тогда: ответ отмечается неверным и показывается эталон
```

Правило сверки:
- регистр и крайние пробелы игнорируются;
- у элемента может быть несколько допустимых ответов, совпадение с любым считается верным;
- строгость сверки — настройка.

### CORE-02-US-3

**Как** Пользователь, **я хочу** отметить «засчитать как верное», если сверка придралась к мелочи, **чтобы** не терять прогресс из-за опечатки или регистра.

Критерии приёмки:
- после исхода «неверно» доступно действие «засчитать как верное»;
- ручной зачёт меняет исход этого ответа на верный;
- действие рассчитано на случай, когда ответ по сути правильный, а сверка придралась к написанию.

## CORE-06 Режим «Заучивание»

Mastery-раунды поверх расписания: материал прогоняется до усвоения, а долгое планирование остаётся за SRS-01. Проверка идёт в формате элемента; смешивание форматов — отдельная фича SRS-03. Роль — Пользователь.

### CORE-06-US-1

**Как** Пользователь, **я хочу** запустить режим «Заучивание» по набору, **чтобы** довести материал до полного усвоения.

```
Сценарий: запуск заучивания
  Дано: открыт набор
  Когда: я запускаю режим «Заучивание»
  Тогда: начинается раунд проверки элементов набора
  И: приоритет отдаётся тем, что пора повторить по расписанию
```

### CORE-06-US-2

**Как** Пользователь, **я хочу** проходить элементы раундами (усвоенные пропадают из списка встречаемых, трудные в этом списке встречаются чаще), **чтобы** запоминать новый материал и повторять при этом старый.

```
Сценарий: раунды до усвоения
  Дано: идёт заучивание
  Когда: я верно отвечаю на элемент нужное число раз подряд
  Тогда: элемент считается усвоенным и выбывает из активной очереди раунда
  Когда: я ошибаюсь на элементе
  Тогда: он возвращается в очередь и встречается чаще
```

### CORE-06-US-3

**Как** Пользователь, **я хочу** видеть прогресс усвоения набора, **чтобы** понимать, сколько ещё до цели.

Критерии приёмки:
- виден прогресс усвоения: сколько элементов усвоено и сколько осталось;
- прогресс обновляется в ходе раундов.

### CORE-06-US-4

**Как** Пользователь, **я хочу** иметь возможность завершать заучивание явно, **чтобы** чётко ставить точку в усвоении материала из набора.

Критерии приёмки:
- заучивание можно завершить явно в любой момент;
- по усвоению всех элементов набора режим предлагает завершить;
- при завершении показывается итог сессии;
- критерий усвоения (N верных подряд) — настройка или алгоритм, числа не фиксируются.

### CORE-06-US-5

**Как** Пользователь, **я хочу** чтобы заучивание опиралось на расписание SRS и кормило его результатами, **чтобы** не терять долгую память ради сиюминутного прогона.

Критерии приёмки:
- заучивание берёт в приоритет то, что пора повторить по расписанию SRS;
- результаты заучивания кормят SRS-записи элементов;
- долгое планирование остаётся за SRS-01.

## CORE-03 Тест с выбором

Вопрос с вариантами, верное подмножество, автодистракторы, счёт. Извлекающий формат. От CORE-03 зависят верно/неверно, викторины, матчи и многоформатная проверка. Роль — Пользователь.

### CORE-03-US-1

**Как** Пользователь, **я хочу** отвечать на вопрос, выбирая из вариантов, **чтобы** проверять узнавание на старте изучения темы.

```
Сценарий: ответ на вопрос с выбором
  Дано: показан вопрос с вариантами ответа
  Когда: я выбираю вариант и подтверждаю
  Тогда: ответ сверяется с верным подмножеством и отмечается верным или неверным
```

### CORE-03-US-2

**Как** Пользователь, **я хочу** чтобы неверные варианты подставлялись сами из набора, **чтобы** не собирать варианты вручную.

Критерии приёмки:
- дистракторы подставляются автоматически из других элементов набора;
- верный вариант берётся из самого элемента;
- если дистракторов не хватает (набор мал), формат недоступен для этого элемента (как в SRS-03-US-2).

### CORE-03-US-3

**Как** Пользователь, **я хочу** отвечать на вопросы с одним и с несколькими верными ответами, **чтобы** покрывать материал, где верных ответов больше одного.

```
Сценарий: несколько верных ответов
  Дано: у вопроса несколько верных вариантов
  Когда: я отмечаю выбранные варианты и подтверждаю
  Тогда: ответ верен, только если выбрано всё верное подмножество и ничего лишнего
```

Дополнительно:
- поддерживаются вопросы с одним верным и с несколькими верными ответами.

### CORE-03-US-4

**Как** Пользователь, **я хочу** видеть счёт и разбор по итогу теста, **чтобы** понять, где ошибся.

Критерии приёмки:
- по итогу теста показан счёт;
- по каждому вопросу видно верно/неверно и правильный ответ;
- результат каждого вопроса кормит SRS-запись элемента.

## CORE-05 Сопоставление

Подбор пар термин–определение порциями, мгновенная проверка, мультиюнит-исход. Извлекающий формат. Роль — Пользователь.

### CORE-05-US-1

**Как** Пользователь, **я хочу** сопоставлять элементы в пары (термин ↔ определение), **чтобы** через активный подбор закрепить, что с чем соотносится на нескольких парах.

```
Сценарий: сопоставление пар
  Дано: показана порция элементов для сопоставления
  Когда: я сопоставляю термин и определение
  Тогда: пара принимается к проверке
```

Дополнительно:
- пары подаются порциями, размер порции — настройка;
- механика подбора (перетаскивание или выбор) оставлена реализации.

### CORE-05-US-2

**Как** Пользователь, **я хочу** сразу видеть, верно ли собрал пару, **чтобы** тут же исправить ошибочную связь.

Критерии приёмки:
- собранная пара проверяется сразу;
- верная пара фиксируется;
- неверная пара сразу отменяется, её элементы возвращаются к подбору.

### CORE-05-US-3

**Как** Пользователь, **я хочу** чтобы результат засчитывался по каждой паре отдельно, **чтобы** SRS корректно подсчитывал мастерство по каждому элементу.

Критерии приёмки:
- упражнение затрагивает несколько элементов (пар) — мультиюнит-исход;
- Результат проверки формируется по каждой паре отдельно;
- каждый результат кормит свою SRS-запись (модель §2).

## CORE-07 Верно/неверно

Утверждение с выбором да/нет (вырожденный выбор из двух опций). Утверждение и флаг истинности задаёт автор элемента, автодистракторы не нужны. Обратная связь мгновенная. Извлекающий формат. Роль — Пользователь.

### CORE-07-US-1

**Как** Пользователь, **я хочу** отвечать «верно / неверно» на утверждение, **чтобы** быстро прогонять материал на старте.

Критерии приёмки:
- показывается утверждение с выбором «верно / неверно»;
- я отвечаю одной из двух опций;
- ответ сверяется с флагом истинности элемента.

### CORE-07-US-2

**Как** Пользователь, **я хочу** видеть, прав я или нет, с верным ответом, **чтобы** закрепить начальное правильное понимание.

Критерии приёмки:
- после ответа сразу видно, прав я или нет;
- показывается верный ответ;
- результат кормит SRS-запись элемента.

## CORE-09 Числовой ответ

Ввод числа со сверкой по допуску. На старте сверяется только число, без единиц измерения. Извлекающий формат. Роль — Пользователь.

### CORE-09-US-1

**Как** Пользователь, **я хочу** вписывать числовой ответ на вопрос, **чтобы** работать над запоминанием точных значений: числа, величины, даты.

```
Сценарий: числовой ответ
  Дано: показан вопрос с числовым ответом
  Когда: я ввожу число и подтверждаю
  Тогда: ответ сверяется с эталонным значением по допуску
```

### CORE-09-US-2

**Как** Пользователь, **я хочу** чтобы ответ засчитывался в пределах допуска, **чтобы** не терять зачёт из-за допустимых округления или мелкого отклонения.

Критерии приёмки:
- у элемента задано эталонное значение и допуск (абсолютный или в процентах);
- ответ верен, если отклонение в пределах допуска;
- допуск задаёт автор элемента.

### CORE-09-US-3

**Как** Пользователь, **я хочу** видеть верный ответ и своё отклонение при ошибке, **чтобы** понять, насколько промахнулся от эталона.

Критерии приёмки:
- при ошибке показывается верный ответ;
- показывается отклонение от эталона;
- на старте сверяется только число, единицы измерения вне сверки;
- принимаются оба разделителя дробной части (точка и запятая).

## CORE-04 Пропуски

Текст с пропусками, каждый пропуск проверяется отдельно. Создание пропусков — в редакторе (CREATE), здесь прохождение. Модель текстового элемента и гранулярность пропусков как целей повторения — предмет PDR/ADR (Бэклог). Извлекающий формат. Роль — Пользователь.

### CORE-04-US-1

**Как** Пользователь, **я хочу** заполнять пропуски в тексте, **чтобы** восстанавливать материал по контексту, ранее закреплённому на меньшем проценте регрессии в памяти.

```
Сценарий: заполнение пропусков
  Дано: показан текст с пропусками
  Когда: я вписываю ответ в каждый пропуск и подтверждаю
  Тогда: каждый пропуск сверяется со своим эталоном
```

### CORE-04-US-2

**Как** Пользователь, **я хочу** чтобы каждый пропуск проверялся отдельно, **чтобы** видеть, какие именно места мною были забыты или неправильно запомнены.

Критерии приёмки:
- каждый пропуск проверяется отдельно;
- по тексту формируется мультиюнит-исход (результат по каждому пропуску);
- каждый пропуск планируется как отдельная цель повторения (своя SRS-запись);
- модель текстового элемента и гранулярность пропусков — предмет PDR/ADR.

### CORE-04-US-3

**Как** Пользователь, **я хочу** чтобы сверка пропуска прощала регистр и мелкие отклонения, **чтобы** не терять зачёт на допустимой опечатке.

Критерии приёмки:
- сверка пропуска игнорирует регистр и крайние пробелы;
- у пропуска может быть несколько допустимых ответов;
- строгость сверки — настройка (как в CORE-02).

## CORE-10 Последовательность

Упорядочивание элементов перетаскиванием со сверкой порядка. Исход частичный: засчитывается доля верных позиций. Последовательность — один извлекающий элемент (одна SRS-запись на весь порядок), не мультиюнит. Проверка по подтверждению. Роль — Пользователь.

### CORE-10-US-1

**Как** Пользователь, **я хочу** расставлять элементы в правильном порядке перетаскиванием, **чтобы** учить материал, где важен сам порядок: шаги процесса, этапы, хронология событий.

```
Сценарий: упорядочивание элементов
  Дано: показаны элементы в перемешанном порядке
  Когда: я расставляю их перетаскиванием и подтверждаю
  Тогда: порядок сверяется с эталонным
  И: исход частичный — засчитывается доля верных позиций
```

### CORE-10-US-2

**Как** Пользователь, **я хочу** видеть, какие позиции верны, а какие нет, **чтобы** понять, где сбился порядок и где я допустил ошибку.

Критерии приёмки:
- результат показывается по нажатию кнопки подтверждения, не по ходу перетаскивания;
- поэлементно видно, какие позиции стоят верно, а какие нет;
- показывается эталонный порядок.

### CORE-10-US-3

**Как** Пользователь, **я хочу** чтобы результат учитывался SRS-системой, **чтобы** запоминать только не усвоенные или назначенные последовательности.

Критерии приёмки:
- последовательность — один извлекающий элемент с одной SRS-записью на весь порядок;
- результат проверки учитывается SRS-системой;
- частичный исход передаётся как сигнал усвоения.
