# User Stories

> Потребности пользователя в формате историй. Что строим и в каком порядке: [План платформы](../План%20платформы.md). Реестр фич с ID: [Бэклог](../Бэклог.md). Роли и права: [Роли и доступ](../Роли%20и%20доступ.md). Термины: [Глоссарий](../Глоссарий.md).

Истории сгруппированы по областям, файл на область (индекс ниже). Соглашения, критерии приёмки и определение готовности — здесь, в остальных файлах не дублируются.

## Формат истории

Каждая история — строка:

**Как [роль], я хочу [действие], чтобы [результат].**

Роли берутся из [Роли и доступ](../Роли%20и%20доступ.md) без переопределения.

## ID истории

`<ID фичи>-US-<n>` — например `CORE-01-US-1`. Префикс = ID фичи из [Бэклога](../Бэклог.md) (единый реестр), суффикс = номер истории внутри фичи.

Одна фича = несколько историй. US мельче фичи: фича `CORE-01` «Флеш-карточки» раскрывается в несколько потребностей (показ, переворот, навигация), каждая — своя история.

## Критерии приёмки

Условия, при которых история считается выполненной. Объективные и проверяемые.

Два стиля, выбираются по размеру и контексту истории.

**Сценарий (Дано — Когда — Тогда)** — для поведения с потоком и ветками:

```
Сценарий: переворот карточки
  Дано: открыта карточка лицевой стороной
  Когда: я нажимаю на карточку
  Тогда: она переворачивается и показывает оборот
```

**Чек-лист правил** — для простых и статичных требований:

```
- клик по карточке переворачивает её
- повторный клик возвращает на лицо
- работает на телефоне и десктопе
```

## Definition of Done

Критерии приёмки описывают сам продукт и свои у каждой истории. DoD описывает качество и процесс, одинаков для всех. Два уровня.

### DoD на историю

- код проходит ревью;
- есть тесты на основной сценарий, все зелёные;
- работает на телефоне и десктопе (План §4.5);
- нет регрессий в связанных фичах;
- тексты интерфейса на русском.

### DoD на итерацию

- все истории итерации закрыты по своему DoD;
- нет открытых критических дефектов;
- изменения влиты в основную ветку;
- документация обновлена, если менялась модель или роли;
- ключевой сценарий итерации проверен вживую.
