## MP-02 Realtime-матч

Соревнование по набору в реальном времени: лидерборд, подиум. Счёт за правильность и скорость. Матч поддерживает извлекающие форматы с быстрой авто-проверкой (выбор, верно/неверно, числовой, короткий ввод); форматы без мгновенной авто-оценки (free recall, дивергентные) в гонку не берутся. На старте минимум — тест с выбором (CORE-03), набор форматов расширяется. Протокол realtime-слоя — ADR (Бэклог §85). Роли: хост (Пользователь) и игроки.

### MP-02-US-1

**Как** Пользователь, **я хочу** создать и хостить матч по набору, **чтобы** запоминать материал в режиме соревнования.

```
Сценарий: создание матча
  Дано: у меня есть набор
  Когда: я создаю матч по набору
  Тогда: матч открывается с кодом или ссылкой для входа игроков
  Когда: игроки собрались
  Тогда: я как хост запускаю матч
```

### MP-02-US-2

**Как** Игрок, **я хочу** отвечать на вопросы в реальном времени на скорость, **чтобы** соревноваться с другими игроками.

```
Сценарий: ответы в реальном времени
  Дано: матч запущен
  Когда: всем игрокам показывается вопрос
  Тогда: я отвечаю в отведённое время
  И: очки начисляются за правильность и скорость ответа
```

Дополнительно:
- поддерживаются извлекающие форматы с быстрой авто-проверкой (выбор, верно/неверно, числовой, короткий ввод);
- на старте минимум — тест с выбором (CORE-03);
- форматы без мгновенной авто-оценки в матче не участвуют.

### MP-02-US-3

**Как** Игрок, **я хочу** видеть живой лидерборд по ходу матча, **чтобы** следить за своей позицией и за лидерами гонки.

Критерии приёмки:
- по ходу матча виден лидерборд: топ-N игроков и их очки;
- игрок видит свою позицию и лидеров;
- лидерборд обновляется между вопросами.

### MP-02-US-4

**Как** Игрок, **я хочу** видеть подиум и итог по окончании, **чтобы** узнать победителей и свой результат.

Критерии приёмки:
- по окончании показывается подиум (призёры);
- игрок видит свой итоговый результат;
- ники и счёт видны участникам (решение №9).

### MP-02-US-5

**Как** Игрок, **я хочу** вернуться в матч после обрыва связи, **чтобы** вернуться в ещё не законченный образовательно-игровой процесс.

```
Сценарий: переподключение после обрыва
  Дано: во время матча у меня прервалась связь
  Когда: связь восстанавливается до конца матча
  Тогда: я возвращаюсь в ещё идущий матч на актуальный вопрос
```

Дополнительно:
- устойчивость к слабой сети и массовому входу — НФТ §6;
- детали протокола переподключения — ADR realtime-слоя.

### MP-02-US-6

**Как** Хост, **я хочу** играть в матче командами, а не только лично, **чтобы** соревноваться группами, а не только один на один.

Критерии приёмки:
- хост может включить командный режим при создании матча;
- игроки распределяются по командам;
- очки игроков суммируются в командный счёт;
- лидерборд и подиум считаются по командам.

## MP-03 Вход в матч гостем

Присоединение к матчу по коду или ссылке без регистрации. Данные гостя временные (решение №9): ник, счёт и статистика живут, пока гость в матче или пока сессия не переключилась на другую активность; прогресс в аккаунт не сохраняется. Роли: Гость, хост.

### MP-03-US-1

**Как** Гость, **я хочу** войти в матч по коду или ссылке без регистрации, **чтобы** быстро присоединиться к игре.

```
Сценарий: вход гостем
  Дано: у меня есть код или ссылка на матч, я не вошёл
  Когда: я открываю ссылку или ввожу код
  Тогда: я попадаю в лобби матча как гость
```

### MP-03-US-2

**Как** Гость, **я хочу** задать временный ник для матча, **чтобы** отображаться в лидерборде и на подиуме.

Критерии приёмки:
- гость задаёт ник перед входом в матч;
- ник уникален в пределах матча;
- ник действует только в этом матче.

### MP-03-US-3

**Как** Гость, **я хочу** видеть во время матча счёт, ники и свою позицию, а в конце статистику, **чтобы** участвовать в соревновании наравне с зарегистрированными.

Критерии приёмки:
- во время матча гостю видны счёт, ники и его позиция;
- по окончании видна статистика матча;
- данные гостя временные: не сохраняются после выхода или переключения сессии (решение №9).

### MP-03-US-4

**Как** Гость, **я хочу** после матча получить предложение зарегистрироваться, **чтобы** сохранить свой результат и дальше копить прогресс.

Критерии приёмки:
- после матча гостю показывается предложение зарегистрироваться;
- при регистрации результат матча можно привязать к новому аккаунту;
- без регистрации результат гостя не сохраняется;
- предложение не блокирует выход из матча.

### MP-03-US-5

**Как** Гость, **я хочу** чтобы ник проходил цензурный фильтр, **чтобы** в матче не появлялись оскорбительные имена.

Критерии приёмки:
- ник проходит автоматический цензурный фильтр при вводе;
- нецензурные и оскорбительные ники отклоняются с просьбой выбрать другой;
- фильтр срабатывает до входа в матч.

### MP-03-US-6

**Как** Игрок, **я хочу** пожаловаться на ник другого игрока, **чтобы** сообщить о проскочившем через фильтр нарушении.

Критерии приёмки:
- участник может пожаловаться на ник другого игрока;
- жалоба уходит на модерацию (back-office, [Роли и доступ](../Роли%20и%20доступ.md));
- жалоба дополняет автоматический фильтр, а не заменяет его.

## MP-01 Учебные группы

Сообщество пользователей с общей подборкой наборов и групп наборов. Учебная группа отлична от группы наборов (ORG-01): там личная организация контента, здесь люди и совместное изучение. Контекстные роли Владелец и Участник берутся из [Роли и доступ](../Роли%20и%20доступ.md). Приглашение по ссылке. Прогресс по общим наборам индивидуальный; агрегат по группе — off-scope (учительский слой).

### MP-01-US-1

**Как** Пользователь, **я хочу** создать учебную группу, **чтобы** собрать людей для совместного изучения.

```
Сценарий: создание учебной группы
  Дано: я хочу учиться вместе с другими
  Когда: я создаю учебную группу
  Тогда: группа создаётся, я становлюсь её владельцем
```

### MP-01-US-2

**Как** Владелец группы, **я хочу** приглашать и исключать участников, **чтобы** управлять составом группы.

Критерии приёмки:
- владелец приглашает участников по ссылке-приглашению;
- владелец исключает участников;
- участник составом не управляет.

### MP-01-US-3

**Как** Владелец группы, **я хочу** собрать в группе подборку наборов и групп наборов, **чтобы** делиться с участниками материалами для запоминания.

Критерии приёмки:
- владелец добавляет в группу наборы и группы наборов;
- владелец убирает их из подборки;
- подборка видна всем участникам.

### MP-01-US-4

**Как** Пользователь, **я хочу** вступить в учебную группу по приглашению, **чтобы** учиться вместе с другими.

```
Сценарий: вступление в группу
  Дано: у меня есть приглашение в учебную группу
  Когда: я принимаю приглашение
  Тогда: я становлюсь участником группы
```

### MP-01-US-5

**Как** Участник группы, **я хочу** учить общие наборы группы, **чтобы** заниматься по общему подготовленному материалу.

Критерии приёмки:
- участник видит общую подборку группы;
- участник проходит общие наборы;
- прогресс по ним у каждого участника индивидуальный.

### MP-01-US-6

**Как** Участник группы, **я хочу** выйти из группы, **чтобы** актуализировать свои интересы по группам.

Критерии приёмки:
- участник может выйти из группы;
- после выхода общая подборка группы ему недоступна;
- выход не затрагивает его личный прогресс по наборам, которые есть у него отдельно.

## MP-04 Статистика матча

Лёгкая статистика самого матча: трудные вопросы, кто ошибся, что повторить. Полные отчёты о прогрессе класса — off-scope (TEACH-03). Хосту видна сводка, игроку — свой разбор. Зависит от MP-02.

### MP-04-US-1

**Как** Пользователь, **я хочу** видеть по итогу матча, какие вопросы были трудными для участников, **чтобы** понять, что группа усвоила слабо.

Критерии приёмки:
- хосту по итогу матча видна сводка: трудные вопросы и кто ошибся;
- видно, какие элементы участники усвоили слабо;
- полные отчёты по классу сюда не входят (off-scope, TEACH-03).

### MP-04-US-2

**Как** Игрок, **я хочу** видеть свой разбор: где ошибся, **чтобы** повторить именно эти места.

Критерии приёмки:
- игроку виден свой разбор с ошибочными вопросами;
- по каждому вопросу виден верный ответ;
- гость видит свой разбор временно (решение №9).

### MP-04-US-3

**Как** Пользователь, **я хочу** отправить трудные элементы матча себе на повторение, **чтобы** закрепить слабые места через SRS.

Критерии приёмки:
- трудные для меня элементы матча можно добавить себе на повторение;
- добавленные элементы кормят SRS-расписание;
- действие доступно зарегистрированному пользователю (гость прогресс не копит).
