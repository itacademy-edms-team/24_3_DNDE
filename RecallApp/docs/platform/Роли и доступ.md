# Роли и доступ

> Кто есть на платформе и что каждому разрешено. Отсюда берутся роли для User Stories и будущих PDR по приватности и монетизации. Модель сущностей: [План платформы §2](План%20платформы.md). Термины: [Глоссарий](Глоссарий.md). Сегменты аудитории (маркетинг, не роли): [Стратегия §2](../vision/Стратегия.md).

## Зачем отдельный документ

Сегмент аудитории и техническая роль — разные вещи. Стратегия делит людей на сегменты, чтобы понять, кому продаём. Здесь описаны роли в системе: кто какое действие может выполнить. Один живой человек может быть сразу в нескольких сегментах, но его права определяет роль.

Роль — не единственная ось доступа. Часть прав приходит не от роли, а от **отношения владения** (ты правишь набор, потому что он твой) и от **контекстной роли** внутри учебной группы или матча (владелец/участник группы, хост/игрок матча). Эти источники прав держим раздельно.

## Два приложения

Платформа состоит из двух приложений с раздельными контурами доступа.

- **Публичное приложение.** Основной продукт: обучение, создание контента, библиотека, мультиплеер. Здесь действуют Гость и Пользователь.
- **Служебное приложение (back-office).** Модерация и администрирование. Сюда входят сотрудники, чьи аккаунты помечены соответствующей привилегией.

Привилегия модератора или администратора — флаг на обычном аккаунте Пользователя (вариант A). На публичном сайте такой человек ведёт себя как Пользователь и не видит привилегированных действий. Повышенные права открываются только при входе в служебное приложение. Личность не раздваивается: один человек — один аккаунт, разный доступ в разных приложениях.

Выделение служебного приложения и модель связи аккаунтов — архитектурное решение, кандидат в ADR «Служебное приложение». Здесь фиксируем только распределение прав.

## Глобальные роли

| Роль | Приложение | Статус | Суть |
|------|-----------|--------|------|
| Гость | публичное | активна | Человек без аккаунта. Может участвовать в мультиплеерных матчах и играх, куда его пустили по коду или ссылке-приглашению, как игрок в чужой партии. По ссылке на набор видит только фрагмент (первые несколько элементов) без прохождения. Полные наборы, библиотека и личный прогресс ему недоступны: чтобы учиться и хранить результаты, нужно зарегистрироваться. Гостевой вход существует ради низкого порога входа, а не для раздачи материала. |
| Пользователь | публичное | активна | Любой зарегистрированный аккаунт. Основная роль платформы. Создаёт наборы и элементы, проходит свой и чужой публичный контент, публикует наборы и делится ссылкой, копит прогресс и расписание повторений (SRS), объединяет наборы в группы, вступает в учебные группы и играет в матчах. Создание и обучение не разведены по разным ролям: один и тот же аккаунт и учит, и создаёт. |
| Модератор | служебное | предусмотреть | Сотрудник, следящий за публичным контентом: разбирает жалобы, снимает наборы с публикации, скрывает нарушающий материал. Эти действия доступны только в служебном приложении. На публичном сайте тот же человек остаётся обычным Пользователем. На старте не реализуется, привилегию заводим заранее, чтобы появление модерации UGC не ломало модель прав. |
| Администратор | служебное | предусмотреть | Полный доступ к системе и аккаунтам: управление пользователями, выдача привилегий, настройки платформы. Доступен только в служебном приложении. Как и модератор, пока зарезервирован. |

## Контекстные роли в учебной группе

Эти роли действуют только внутри конкретной учебной группы и не влияют на остальную платформу. Один аккаунт может быть владельцем одной группы и участником другой одновременно.

| Роль | Суть |
|------|------|
| Владелец группы | Пользователь, создавший учебную группу. Управляет её составом (приглашает и исключает участников) и подборкой наборов и групп внутри неё. |
| Участник группы | Пользователь, вступивший в чужую группу. Учится по общей подборке и участвует в совместных активностях, но не меняет ни состав группы, ни её подборку. |

## Контекстные роли в матче

Действуют только внутри конкретного матча и не влияют на остальную платформу. Соответствуют сущностям Матч и Игрок из [модели §2](План%20платформы.md).

| Роль | Суть |
|------|------|
| Хост | Пользователь, создавший матч. Запускает матч и управляет его ходом. |
| Игрок | Участник матча. Может быть Гостем или Пользователем. Отвечает на вопросы, видит лидерборд и свой результат. Гость как игрок может видеть данные в ограниченном по времени и объёме контексте. |

## Матрица прав: публичное приложение

Условные обозначения: ✓ — действие доступно роли напрямую; — — недоступно; **влад.** — право приходит из владения объектом, а не из роли; **группа** — право приходит из контекстной роли владельца группы.

### Аккаунт

| Действие | Гость | Пользователь |
|----------|:-----:|:------------:|
| Зарегистрироваться / войти | ✓ | ✓ |
| Удалить свой аккаунт | — | ✓ |

### Контент: создание

| Действие | Гость | Пользователь |
|----------|:-----:|:------------:|
| Создать набор и элементы | — | ✓ |
| Править / удалить свой набор | — | влад. |
| Объединить наборы в группы и папки | — | ✓ |

### Контент: доступ и прохождение

| Действие | Гость | Пользователь |
|----------|:-----:|:------------:|
| Предпросмотр набора по ссылке (фрагмент) | ✓ | ✓ |
| Пройти свой набор | — | ✓ |
| Пройти чужой публичный набор | — | ✓ |
| Поиск по публичной библиотеке | — | ✓ |
| Сохранить / дублировать чужой набор | — | ✓ |
| Экспорт набора | — | влад. |

### Обучение и прогресс

| Действие | Гость | Пользователь |
|----------|:-----:|:------------:|
| Копить прогресс и расписание SRS | — | ✓ |
| Получать достижения и стрики | — | ✓ |

### Публикация

| Действие | Гость | Пользователь |
|----------|:-----:|:------------:|
| Опубликовать набор и поделиться ссылкой | — | влад. |

### Социальное и мультиплеер

| Действие | Гость | Пользователь |
|----------|:-----:|:------------:|
| Войти в матч по коду / ссылке | ✓ | ✓ |
| Создать и хостить матч | — | ✓ |
| Создать учебную группу | — | ✓ |
| Вступить в учебную группу | — | ✓ |
| Управлять составом и подборкой группы | — | группа |
| Пожаловаться на контент | — | ✓ |

## Матрица прав: служебное приложение

Доступ только для аккаунтов с соответствующей привилегией. В горизонте 8 месяцев эти действия в User Stories не расписываем, секция фиксирует распределение на вырост.

| Действие | Модератор | Администратор |
|----------|:---------:|:-------------:|
| Разобрать жалобу на контент | ✓ | ✓ |
| Снять чужой набор с публикации | ✓ | ✓ |
| Скрыть / заблокировать материал | ✓ | ✓ |
| Управление аккаунтами и привилегиями | — | ✓ |
| Настройки платформы | — | ✓ |

## Границы и следствия

- **Гостю доступен минимум.** Войти в чужой матч по коду или ссылке и посмотреть фрагмент набора по ссылке. Полные наборы, библиотека и прогресс требуют регистрации.
- **Шаринг по ссылке: фрагмент гостю, прохождение за логином.** По ссылке гость видит фрагмент набора (первые несколько элементов) без прохождения. Любой учебный режим, сохранение и прогресс требуют входа (ORG-02). Объём фрагмента — настройка.
- **Элемент всегда в наборе.** Отдельный элемент вне набора не существует. Быстрая флеш-карточка всё равно попадает в набор (возможно, в дефолтный). Модель из [Плана §2](План%20платформы.md) остаётся в силе.
- **Модерация и администрирование — в служебном приложении.** На публичном сайте привилегированных действий нет. Выделение back-office и модель связи аккаунтов уходят в ADR «Служебное приложение».
