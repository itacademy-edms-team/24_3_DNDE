# Бэклог

> Канонический список фич с ID, оценкой, зависимостями и помесячными слотами. Отсюда берутся фичи на реализацию. Крупные статусы и фазы: [План платформы §3/§5](План%20платформы.md). Рыночный контекст: [Матрица функционала](../competitors/Матрица%20функционала.md).
> Горизонт 8 месяцев, каждая фича ≈ неделя. Собрано 2026-10-05.
> Темп неравномерный: M4 уплотнён (5 фич), в M2 четыре, остальные месяцы по 2–3. Средняя ≈3.1 фичи в месяц.

## Соглашения

- **ID**: префикс по домену + номер. Это канонический реестр ID; матрица и будущие PDR/ADR ссылаются сюда.
- **Размер**: `S` ≈ полнедели, `M` ≈ неделя, `L` ≈ две недели.
- **Статус**: `committed` в плане на горизонт; `ext` буфер, берётся при наличии ёмкости.
- **Слот**: целевой месяц `M1…M8`; у `ext` слота нет (плавающие).
- Зависимость: фича не стартует раньше указанной.

Распределение: 25 committed-фич по M1–M8 (с запасом в слотах), 6 ext в буфер. Итого 31. Плюс 3 off-scope (учительский слой, вне горизонта).

## Критический путь

`ACCT-01 → CREATE-01 → CORE-01 → CORE-02 → SRS-01 → {CORE-06, SRS-02, SRS-03}`. Это ядро обучения. Параллельно от `CREATE-01` идут `ORG-*`. Мультиплеер (`MP-02`) упирается в `CORE-03`. Циклов нет.

## Что потребует Decision Records

- `SRS-01` → **ADR**: алгоритм интервалов (SM-2 / FSRS / свой). См. План §7.1.
- `MP-02` → **ADR**: realtime-слой (протокол, устойчивость к слабой сети).
- `CORE-04` → **PDR/ADR**: модель текстового элемента и границы пропусков как целей повторения.
- Платные пороги (что из `ext`/`off-scope` монетизируем) → **PDR**. См. Стратегия §6.
- Служебное приложение (модерация и админ отдельным приложением, модель связи аккаунтов) → **ADR**. См. План §4.7.
